# P0 / P1 / P2 稳定性优化报告

## 范围

本轮执行 P0 的 1、2、5，以及全部 P1、P2。按约定没有改动微信发送实现，也没有调整 SSH/root 登录策略。

## P0

- 修复待办提醒扫描中未声明函数导致的持续失败，记录最近成功、最近错误和恢复状态，并加入完整扫描链测试。
- Web/Worker 统一优雅退出：先停止调度与接收请求，再关闭 HTTP、SQLite 主库和词典库；超时连接会被收口，正常停止不再伪报崩溃。
- HBR 异地备份改为启动前、启动后双重健康和压力检查，结果写入健康中心；阈值允许已观测到的正常 HBR 启动峰值，但仍会在超预算时自动停止。

## P1

- 升级运行依赖并清零生产依赖高危漏洞。
- 深度健康检查新增待办提醒任务、最近失败后台任务、HBR 窗口结果和构建版本。
- Break Guard 秒级 UI 与数据库汇总解耦；日切和进度检查降频，课程配置按内容去重，断网采用指数退避。
- Break Guard 自动剔除休眠、长时间事件循环停顿和 Windows 锁屏时间，不再把不可观察时段计入课程。
- Break Guard 1.0.0 产物带文件版本和 SHA-256 清单；登录计划任务支持异常退出重启，桌面快捷方式指向当前稳定目录。
- 网页网络状态改为全站单例探测，连接恢复后自动清理响应缓存并重新验证数据。
- 专注计时离线操作遇到 4xx/409 时进入可见冲突箱，可重试或明确采用服务器状态，不再静默删除。

## P2

- 生产运行时移除 `Function.toString()` 依赖推断，28 个领域模块改用版本控制内的显式能力清单，CI 检查清单漂移。
- API GET 缓存真正执行 TTL 和并发合并；失败响应不缓存，写操作立即清缓存。
- 会话、首页、状态和专注计时关键响应加入运行时结构校验。
- 主题只保留 `apple-tokens.css` 一套来源；页面直接色阶类迁移为语义色并由 CI 禁止回流。
- Dexie 迁移到 `src/legacy/indexedDb`，只在旧数据迁移页面加载；当前服务器 SQLite 与旧浏览器库不再概念混用。
- PWA 缓存升级，公共资源预缓存；动态模块版本失配在线自动恢复。
- 应用版本升级为 1.0.0，构建写入可追溯元数据。
- CI 扩展到所有分支，覆盖漏洞审计、Node/Python 测试、Shell 校验、构建预算和 Chromium E2E。
- 旧原地覆盖部署入口退役，统一使用候选验证、数据库快照、原子切换和失败回滚流程。

## 验证基线

- Vitest：141 项通过。
- Break Guard unittest：40 项通过。
- Chromium E2E：6 项通过，覆盖核心导航、深色模式、专注开始/结束和冲突可见性。
- TypeScript/Vite 生产构建：通过。
- 首屏 JS：404,566 bytes，低于 900,000 bytes 预算。
- `npm audit --omit=dev`：0 个漏洞。
- Break Guard EXE：1.0.0，打包成功，SHA-256 已写入本机构建清单。

## 客观限制

- 当前服务器物理内存约 2 GB，软件层已经限并发、限内存和错峰重 I/O，但软件无法替代硬件扩容。
- 本机没有受信任的 Windows 代码签名证书，因此 EXE 为未签名产物；启动器继续优先使用受系统信任的 Python 运行时，不绕过 Smart App Control。
